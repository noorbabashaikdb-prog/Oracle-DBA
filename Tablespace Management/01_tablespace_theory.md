# Oracle Tablespace Management – Theory

## 1. Tablespace – Definition

A **tablespace** is a **logical storage container inside an Oracle database** used to organize and manage database objects such as:

* Tables
* Indexes
* Views
* Materialized views
* LOB segments
* Other schema objects

A tablespace consists of one or more **physical datafiles**.

### Simple Definition

> **Tablespace = Logical storage container**
>
> **Datafile = Physical storage file**

### Basic Structure

```text
                 ORACLE DATABASE
                       |
        +--------------+--------------+
        |              |              |
      SYSTEM          USERS          TEMP
        |              |              |
    Datafile        Datafile        Tempfile
        |              |              |
      Disk           Disk           Disk
```

---

# 2. Logical vs Physical Storage

Oracle storage is divided into two major levels.

```text
        ORACLE DATABASE
               |
        +------+------+
        |             |
     LOGICAL       PHYSICAL
        |             |
    Tablespace     Datafiles
        |             |
      Segments       OS Files
        |
      Extents
        |
      Blocks
```

### Logical Storage Hierarchy

```text
Database
   |
Tablespace
   |
Segment
   |
Extent
   |
Oracle Block
```

### Definitions

**Database:**
A collection of physical files managed by Oracle Database.

**Tablespace:**
A logical storage container within the database.

**Segment:**
Storage allocated for a database object.

Examples:

* Table segment
* Index segment
* Undo segment
* LOB segment

**Extent:**
A group of contiguous Oracle blocks allocated to a segment.

**Block:**
The smallest unit of logical storage used by Oracle Database.

---

# 3. Tablespace and Datafile Relationship

A tablespace can contain one or more datafiles.

```text
             TABLESPACE
                  |
       +----------+----------+
       |          |          |
   Datafile1   Datafile2   Datafile3
       |          |          |
      Disk       Disk       Disk
```

Example:

```sql
CREATE TABLESPACE app_data
DATAFILE '/u01/oradata/ORCL/app_data01.dbf'
SIZE 1G;
```

Here:

* `APP_DATA` = Tablespace
* `app_data01.dbf` = Datafile
* `1G` = Initial size

---

# 4. Why Do We Need Tablespaces?

Tablespaces provide logical organization and storage management.

### Main purposes

1. Organize database objects
2. Manage storage
3. Control space allocation
4. Improve administration
5. Separate application data
6. Manage quotas
7. Support backup and recovery strategies
8. Manage temporary and undo storage
9. Support read-only databases
10. Support ASM storage

Example:

```text
             DATABASE
                |
      +---------+---------+
      |         |         |
   SYSTEM     APP_DATA   APP_INDEX
      |         |         |
   Oracle     Tables      Indexes
   metadata
```

---

# 5. Types of Tablespaces

Oracle commonly uses the following types:

1. Permanent Tablespace
2. Temporary Tablespace
3. Undo Tablespace
4. Read-Only Tablespace
5. Bigfile Tablespace
6. Smallfile Tablespace

---

# 6. Permanent Tablespace

A **permanent tablespace** stores permanent database objects.

Examples:

* Tables
* Indexes
* LOBs

Example:

```sql
CREATE TABLESPACE users_data
DATAFILE '/u01/oradata/ORCL/users_data01.dbf'
SIZE 500M
AUTOEXTEND ON
NEXT 100M
MAXSIZE 5G;
```

---

# 7. Temporary Tablespace

A **temporary tablespace** is used for temporary operations that require disk space.

Examples:

* Sort operations
* Hash joins
* ORDER BY
* GROUP BY
* CREATE INDEX
* Temporary result sets

Temporary tablespaces use **tempfiles** rather than normal datafiles.

```text
             TEMP TABLESPACE
                    |
          +---------+---------+
          |                   |
      tempfile01          tempfile02
```

Example:

```sql
CREATE TEMPORARY TABLESPACE temp01
TEMPFILE '/u01/oradata/ORCL/temp01.dbf'
SIZE 1G
AUTOEXTEND ON
NEXT 100M
MAXSIZE 5G;
```

---

# 8. Undo Tablespace

An **undo tablespace** stores undo information generated by transactions.

Undo is required for:

* Transaction rollback
* Read consistency
* Flashback operations
* Transaction recovery

Example:

```sql
CREATE UNDO TABLESPACE undotbs02
DATAFILE '/u01/oradata/ORCL/undotbs02.dbf'
SIZE 1G;
```

---

# 9. SYSTEM Tablespace

The **SYSTEM tablespace** is a mandatory Oracle tablespace.

It contains important Oracle data dictionary information.

Examples include:

* Data dictionary
* System metadata
* Internal Oracle objects

The SYSTEM tablespace cannot be dropped while the database is operating normally.

---

# 10. SYSAUX Tablespace

The **SYSAUX tablespace** is an auxiliary tablespace for SYSTEM.

It stores various Oracle components and repository data.

Examples can include:

* AWR-related data
* Oracle components
* Enterprise Manager-related information
* Other Oracle internal repositories

SYSAUX helps reduce the amount of data stored in SYSTEM.

---

# 11. USERS Tablespace

The **USERS** tablespace is commonly used as a default permanent tablespace for database users.

Example:

```sql
CREATE USER appuser
IDENTIFIED BY password
DEFAULT TABLESPACE users;
```

The user's objects are created in the default tablespace unless another tablespace is specified.

---

# 12. Read-Only Tablespace

A tablespace can be placed into **READ ONLY** mode.

Example:

```sql
ALTER TABLESPACE app_data READ ONLY;
```

In read-only mode:

* Existing data can be queried.
* New objects cannot normally be created there.
* Existing objects cannot be modified.

To return to read/write:

```sql
ALTER TABLESPACE app_data READ WRITE;
```

---

# 13. Bigfile Tablespace

A **bigfile tablespace** contains one very large datafile.

```text
BIGFILE TABLESPACE
        |
     Datafile
        |
   Very Large File
```

Example:

```sql
CREATE BIGFILE TABLESPACE big_data
DATAFILE '/u01/oradata/ORCL/big_data01.dbf'
SIZE 10G;
```

Advantages:

* Simplifies file management
* Suitable for very large databases
* Fewer datafiles to manage

---

# 14. Smallfile Tablespace

A **smallfile tablespace** can contain multiple datafiles.

```text
SMALLFILE TABLESPACE
        |
   +----+----+----+
   |    |    |    |
 DF1  DF2   DF3  DF4
```

Example:

```sql
CREATE TABLESPACE app_data
DATAFILE
'/u01/oradata/ORCL/app01.dbf' SIZE 1G,
'/u01/oradata/ORCL/app02.dbf' SIZE 1G;
```

---

# 15. Bigfile vs Smallfile

| Feature             | Smallfile            | Bigfile            |
| ------------------- | -------------------- | ------------------ |
| Number of datafiles | Multiple             | One                |
| File management     | More files           | Easier             |
| Large database      | Suitable             | Very suitable      |
| Default type        | Common/default       | Explicitly created |
| Administration      | More files to manage | Simpler            |

---

# 16. Locally Managed Tablespace

A **locally managed tablespace (LMT)** stores extent-management information inside the tablespace itself using bitmaps.

Example:

```sql
CREATE TABLESPACE app_data
DATAFILE '/u01/oradata/ORCL/app_data01.dbf'
SIZE 1G
EXTENT MANAGEMENT LOCAL;
```

Locally managed tablespaces are the standard choice in modern Oracle databases.

---

# 17. Dictionary Managed Tablespace

A **dictionary managed tablespace (DMT)** uses the Oracle data dictionary to manage extent allocation.

This is an older storage-management method.

Modern Oracle databases generally use **locally managed tablespaces**.

---

# 18. Automatic Segment Space Management

**ASSM** stands for **Automatic Segment Space Management**.

It allows Oracle to manage free space inside segments automatically.

Example:

```sql
CREATE TABLESPACE app_data
DATAFILE '/u01/oradata/ORCL/app_data01.dbf'
SIZE 1G
SEGMENT SPACE MANAGEMENT AUTO;
```

Advantages:

* Automatic free-space management
* Reduced manual tuning
* Better concurrency
* Recommended for most application tablespaces

---

# 19. Extent Management

An **extent** is a collection of Oracle blocks allocated to a segment.

```text
             SEGMENT
                |
       +--------+--------+
       |        |        |
    Extent1  Extent2  Extent3
       |        |        |
    Blocks   Blocks   Blocks
```

When a segment requires additional space, Oracle allocates another extent.

---

# 20. Uniform Extent Size

A tablespace can use uniform extent sizes.

Example:

```sql
CREATE TABLESPACE app_data
DATAFILE '/u01/oradata/ORCL/app_data01.dbf'
SIZE 1G
EXTENT MANAGEMENT LOCAL
UNIFORM SIZE 1M;
```

Every extent is allocated with the specified size.

---

# 21. AUTOALLOCATE

Oracle can automatically determine appropriate extent sizes.

Example:

```sql
CREATE TABLESPACE app_data
DATAFILE '/u01/oradata/ORCL/app_data01.dbf'
SIZE 1G
EXTENT MANAGEMENT LOCAL
AUTOALLOCATE;
```

Oracle automatically manages extent sizing.

---

# 22. AUTOEXTEND

**AUTOEXTEND** allows a datafile or tempfile to automatically increase when more space is required.

Example:

```sql
CREATE TABLESPACE app_data
DATAFILE '/u01/oradata/ORCL/app_data01.dbf'
SIZE 1G
AUTOEXTEND ON
NEXT 100M
MAXSIZE 5G;
```

Definitions:

* `SIZE 1G` → Initial size
* `AUTOEXTEND ON` → Automatic growth enabled
* `NEXT 100M` → Growth increment
* `MAXSIZE 5G` → Maximum file size

---

# 23. MAXSIZE

`MAXSIZE` defines the maximum size to which an autoextensible datafile can grow.

Example:

```sql
AUTOEXTEND ON
NEXT 100M
MAXSIZE 10G
```

The file can grow up to 10 GB.

---

# 24. Unlimited Growth

Example:

```sql
AUTOEXTEND ON
NEXT 100M
MAXSIZE UNLIMITED;
```

This allows Oracle to continue growing the file subject to Oracle and underlying storage limits.

**Important:** `MAXSIZE UNLIMITED` does not mean the physical disk has unlimited space.

---

# 25. Datafile Resize

A datafile can be manually increased.

```sql
ALTER DATABASE DATAFILE
'/u01/oradata/ORCL/app_data01.dbf'
RESIZE 2G;
```

This increases the datafile to 2 GB.

---

# 26. Add Datafile

Instead of resizing an existing file, a new datafile can be added.

```sql
ALTER TABLESPACE app_data
ADD DATAFILE
'/u01/oradata/ORCL/app_data02.dbf'
SIZE 1G
AUTOEXTEND ON
NEXT 100M
MAXSIZE 5G;
```

---

# 27. Tablespace Full Situation

A tablespace can become full because of:

* Data growth
* Index growth
* LOB growth
* Autoextend disabled
* Maximum file size reached
* Filesystem full
* ASM disk group full
* Datafile size limitation

Typical error:

```text
ORA-01653: unable to extend table
```

Example troubleshooting flow:

```text
Tablespace Full
      |
      v
Check Free Space
      |
      v
Check Datafile Size
      |
      v
Check AUTOEXTEND
      |
      v
Check MAXSIZE
      |
      v
Check Filesystem / ASM
      |
      +------+
      |      |
    Resize  Add Datafile
```

# 28. Tablespace Usage Monitoring

Basic query:

```sql
SELECT
    tablespace_name,
    status,
    contents,
    extent_management,
    segment_space_management
FROM dba_tablespaces
ORDER BY tablespace_name;
```

---

# 29. Datafile Monitoring

```sql
SELECT
    file_id,
    file_name,
    tablespace_name,
    bytes/1024/1024 AS size_mb,
    autoextensible,
    maxbytes/1024/1024 AS max_size_mb
FROM dba_data_files
ORDER BY tablespace_name, file_id;
```

---

# 30. Free Space Monitoring

```sql
SELECT
    tablespace_name,
    SUM(bytes)/1024/1024 AS free_mb
FROM dba_free_space
GROUP BY tablespace_name
ORDER BY tablespace_name;
```

# 32. Tablespace Online / Offline

Take a tablespace offline:

```sql
ALTER TABLESPACE app_data OFFLINE;
```

Bring it online:

```sql
ALTER TABLESPACE app_data ONLINE;
```

For normal production operations, always understand the impact before taking a tablespace offline.

---

# 33. Dropping a Tablespace

Example:

```sql
DROP TABLESPACE app_data
INCLUDING CONTENTS
AND DATAFILES;
```

Meaning:

* `INCLUDING CONTENTS` → Drop objects inside the tablespace.
* `AND DATAFILES` → Remove associated datafiles.

**Warning:** This is a destructive operation.

---

# 34. Default Permanent Tablespace

The database has a default permanent tablespace.

Check it:

```sql
SELECT property_name, property_value
FROM database_properties
WHERE property_name LIKE '%TABLESPACE%';
```

Set a default permanent tablespace:

```sql
ALTER DATABASE DEFAULT TABLESPACE app_data;
```

---

# 35. Default Temporary Tablespace

Check:

```sql
SELECT property_name, property_value
FROM database_properties
WHERE property_name = 'DEFAULT_TEMP_TABLESPACE';
```

Set:

```sql
ALTER DATABASE DEFAULT TEMPORARY TABLESPACE temp01;
```

---

```sql
    temporary_tablespace
```

```text
USERNAME     DEFAULT_TABLESPACE     TEMPORARY_TABLESPACE

```

# 37. Tablespace Quota

A quota controls how much space a user can consume in a tablespace.

Example:

```sql
ALTER USER appuser
QUOTA 2G ON app_data;
```

Unlimited quota:

```sql
ALTER USER appuser
QUOTA UNLIMITED ON app_data;
```
